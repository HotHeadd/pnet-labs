У каждой лабы своя папка `labN/` (или `<предмет>/labN/`) со своим `CLAUDE.md` — состояние стенда и что осталось. Читай его первым, когда работаешь с лабой.

## Работа с PNETLab через MCP

MCP-сервер `pnetlab`, аккаунт PNET `mcp-vova` (роль Admin). PNETLab 5.x, offline-режим.

- **Одна сессия на аккаунт.** Если одновременно открыт Claude Desktop с тем же MCP — вы выбиваете друг друга. Работай из одного клиента.
- **Свой экземпляр лабы.** Под `mcp-vova` у каждой лабы свой pod: изменения в консолях видны только в этой сессии. Пользователь смотрит через Join в веб-морде (Running Lab). Чужие сессии (других аккаунтов) MCP не видит и не трогает.
- **Перед изменениями** — `get_lab`, сверить id нод и интерфейсы. IOL-индексы: e0/0=0, e0/1=16, e0/2=32, e0/3=48, e1/0=1, e1/1=17 и т. д. (можно передавать имя `e0/1`).
- **Консоль теряет символы на длинных пачках.** `send_console` — блоками по 5–10 строк; после блока проверять `show run | include ...` через `read_console`.
- **Новые IOL-ноды** при первом старте висят в `initial configuration dialog` — сначала отправить `no`.
- **`read_console` возвращает скриншот**, не текст:
  - вывод пинга VPCS туда не попадает — связность проверять по счётчикам на IOL (`show ip nat translations`, `show ip access-lists`, `show ip dhcp binding`, ping с IOL);
  - пустой экран — повторить с пустыми строками в начале и конце списка команд;
  - для отчёта вывод переписывать со скриншота дословно; если не читается — попросить пользователя скопировать вывод из консоли в браузере.
- **IOL L2:** перед `vlan N` нужен `vtp mode transparent`, иначе VLAN не попадут в конфиг. **VPCS** игнорирует startup-config — IP только через консоль (`ip ...`, `save`).
- **Сохранение:** после изменений `write memory` на устройстве + `export_config` (node_id=0). Проверка — `get_node_config`. Флаг загрузки startup-config (`config`) MCP менять не умеет: если у нод `config: 0`, попросить пользователя включить его в веб-морде.
- **Не вызывать без прямой просьбы:** `stop_lab`, `delete_lab`, `wipe_node`, `delete_node` — они уничтожают состояние (`stop_lab` — сразу всех сессий лабы).
- **Таймауты.** Если MCP перестал отвечать — скорее всего, Мак уснул. Не повторять команды вслепую: сначала `list_running_labs`, потом проверить, что успело примениться.

## Автосборка отчёта по лабе

Когда просят «сделай отчёт по лабе N» / «оформи лабу <имя в PNETLab>»:

1. Если папки лабы нет — `./new-lab.sh labN` (или `<предмет>/labN`).
2. Через MCP найти лабу (`list_labs`, `get_lab`): узлы, линки, сети.
3. Конфиги: `export_config` (node_id=0), затем `get_node_config` по каждому настраиваемому узлу →
   `labN/configs/<узел>.txt` (только итоговый конфиг; убрать пустые `!`, баннеры и служебные строки PNET вроде `no shutdown` на неиспользуемых портах).
4. Проверки: если лаба запущена — `send_console` + `read_console` с нужными
   show/ping/traceroute → `labN/outputs/<узел>-<что>.txt` (вывод переписать со скриншота дословно). Если не запущена — спросить,
   запускать ли (`start_all`), не запускать самовольно.
5. Топология: скриншот схемы через MCP не получить — оставить заглушку
   `img/topology.png` и попросить пользователя вставить скрин из веб-интерфейса,
   либо нарисовать схему прямо в typst по данным `get_lab`.
6. Заполнить `labN/main.typ`: номер, тему, дисциплину, преподавателя (спросить, если неизвестно),
   разделы «Цель работы», «Задание» (из текста задания, если дан), «Ход работы»
   (топология → адресация таблицей → настройка по устройствам → проверка), «Заключение».
   Каждый листинг/рисунок — с меткой и ссылкой на него в тексте.
7. Собрать `typst compile labN/main.typ`, открыть PDF и проверить глазами.

Не трогать `mephi-labs/` без явной просьбы — он общий для всех отчётов.
