# Работа в команде со стендами PNETLab

Стенды лаб живут на общем сервере PNETLab (`http://100.100.57.19`, доступ через Tailscale). Настраивает их
ассистент Claude Code по этому репозиторию: правила для него — в `CLAUDE.md`, здесь — что нужно сделать людям.

## Как устроено (коротко)

- Каждый аккаунт PNETLab, открывший лабу, получает **свою копию** запущенной лабы (pod). Что меняется в консолях,
  видно только в ней.
- Общее для всех — **опубликованное** состояние: схема и конфиги Cisco (IOL) хранятся в самом файле лабы, а настроенные
  Linux/Windows-узлы сохраняются как отдельные образы на сервере. Публикует ассистент в конце работы.
- С одной лабой одновременно работает один человек. Кто её держит, видно по замку: строка `LOCK: …` в описании лабы
  (видна и в веб-интерфейсе).

## Аккаунты

| Человек | Для ассистента (MCP) | Для браузера |
|---|---|---|
| Влад | `vlad_pc` | `vlad` |
| Вова | `vova_pc` | `vladimir` |
| Серёжа | `serj_pc` | `serjei` |
| Миша | `micha_pc` | `micha` |

Один и тот же логин в MCP и в браузере выбивают друг друга. Поэтому в браузер заходим **своим веб-аккаунтом**, а работу
ассистента смотрим через **Join**: Running Labs → нужная лаба → сессия своего `*_pc` → Join.

Если веб-интерфейс при входе сразу открывает какую-то лабу и не выпускает: у вашего веб-аккаунта осталась открытая
сессия. Попросите ассистента: «покажи сессии и закрой мою пустую», он выполнит `pnet-helper.py sessions` / `close-session`.

## Настройка (один раз)

1. Tailscale в сети команды — открывается `http://100.100.57.19`.
2. Репозиторий: `git clone git@github.com:HotHeadd/pnet-labs.git`, для отчётов — typst (см. `README.md`).
3. MCP-сервер:
   ```sh
   git clone https://github.com/omichelbraga/pnetlab-mcp-server ~/mcp/pnetlab-mcp-server
   cd ~/mcp/pnetlab-mcp-server && python3 -m venv .venv && .venv/bin/pip install -e .
   ```
4. Креды: `cp mcp-creds.example.json mcp-creds.json` и вписать пароли четырёх `*_pc`.
   **Репозиторий публичный:** `mcp-creds.json` в `.gitignore`, не добавлять его в git (`git add -f`) и не вписывать пароли в шаблон.
   Аккаунт MCP выбирает ассистент под лабу (`start-lab`), вручную — `tools/pnet-helper.py use vlad_pc`.
5. `.mcp.json` уже в репозитории: MCP запускается через `tools/pnet-mcp.sh` из venv `~/mcp/pnetlab-mcp-server/.venv`
   (другое место — переменная `PNETLAB_MCP_PY=<venv>/bin/python`). На Windows без `sh` — локально заменить команду на
   `<venv>\Scripts\python.exe tools\pnet-mcp.py` и не коммитить.
6. Запустить `claude` в корне репозитория и разрешить MCP-сервер `pnetlab`.
7. Только для публикации Linux/Windows-узлов в образы: свой SSH-ключ на сервер (один раз, пароль root — у команды, вне git):
   `ssh-copy-id -i ~/.ssh/id_ed25519.pub root@100.100.57.19`. Без него можно работать, но не публиковать.

## Порядок работы

1. «Возьми лабу BKS3» — ассистент выполнит `start-lab`: если лабу держит другой (замок) — остановится и скажет кто;
   если у лабы есть живая сессия — возьмёт аккаунт её автора (попадёте в ту же копию с настроенными узлами);
   иначе — свободный аккаунт (без сессий с запущенными узлами); лабы нет — создаст. Потом попросит
   **/mcp → pnetlab → Reconnect**, чтобы MCP перешёл на этот аккаунт.
2. Работаете с ассистентом как обычно.
3. Закончили — «сохрани и отпусти лабу»: конфиги IOL сохраняются в лабу, выгрузка — в `<лаба>/stand/`, замок снимается.
   Сессия (копия с узлами) **остаётся висеть** под тем же аккаунтом — следующий человек возьмёт её через `start-lab`.
4. «Опубликуй лабу» (по запросу, например перед сдачей) — Linux/Windows-узлы сворачиваются в образы на сервере.
   Тогда лаба откроется настроенной под любым аккаунтом, даже если сессию кто-то закроет.

Чего не делать: не останавливать лабу целиком (Stop/Destroy Lab в веб-интерфейсе рушит копии **всех** участников)
и не стирать (Wipe) чужие узлы.
