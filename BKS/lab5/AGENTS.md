# БКС, лабораторная работа №5

Вариант 5. Suricata в режиме IDS обнаруживает обращения к путям административных панелей, загрузку файлов с тестовыми именами и превышение порога ICMP Echo Request. Для сравнения `alert` и `drop` предусмотрен отдельный тест одного HTTP-правила в режиме IPS.

## Состояние на 2026-11-19

- Создана отдельная лаба `/BKS labs/BKS5.unl`. PNETLab подтвердил три запущенных узла в сессии 10.
- Узлы используют `linux-ubuntu-server-22.04`: CLIENT (1), SURICATA (2), HTTP-SERVER (3). CLIENT e0 и SURICATA e0 подключены к TEST-NET, SURICATA e1 и HTTP-SERVER e0 — к SERVER-NET. Оба сегмента — внутренние bridge-сети PNETLab.
- В `preamble/` сохранена методичка. В `stand/` сохранена выгрузка топологии.
- Предлагаемая адресация: CLIENT `192.168.100.10/24`, SURICATA `192.168.100.2/24` и `10.1.50.1/24`, HTTP-SERVER `10.1.50.10/24`. На конечных узлах маршруты к соседнему сегменту через SURICATA.
- Предстоит настроить гостевые ОС, установить Suricata и HTTP-сервер, подтвердить связность, проверить три правила и сохранить реальные журналы. Для порога ICMP использовать небольшое число обычных Echo Request с низким порогом тестового правила. Для HTTP использовать локальные тестовые файлы и URL.
