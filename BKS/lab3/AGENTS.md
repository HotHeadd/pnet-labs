## Журнал 2026-10-27

- Развёрнуты пять Ubuntu 22.04 с индивидуальными cloud-init seed ISO. Исходный
  образ `linux-ubuntu-server-22.04` не изменён; добавлены тонкие образы
  `linux-bks3-hq-gw`, `linux-bks3-br-gw`, `linux-bks3-hq-srv`,
  `linux-bks3-br-client`, `linux-bks3-xray-relay` с собственными seed.
- У PNETLab базовый Ubuntu уже содержит cdrom.iso; добавлять второй `-cdrom`
  через qemu_options нельзя. В итоговой конфигурации используется штатный cdrom
  соответствующего нового образа. Все узлы имеют реальные параметры шаблона linux.
- WAN 203.0.113.0/24, HQ .10, BR .20, relay .30. GRE 172.16.0.0/30:
  HQ .1, BR .2. Сеть управления pnet0, адреса .211–.215 в порядке узлов.
- IKEv2 / strongSwan 5.9.5, transport mode, GRE selectors 47,
  IKE AES256-SHA256-MODP2048, ESP AES256-GCM. PSK только на узлах/хосте,
  в публичных файлах отсутствует. Межофисного NAT нет.
- FRRouting: сосед Full, удалённые LAN установлены как proto ospf, LAN passive,
  hello/dead 2/8, MTU 1400. ICMP 4/4, HTTP с source 10.2.20.42, traceroute
  через оба шлюза, DF-пакет 1400 байт — успешно. На WAN-мосту vnet8_1 только ESP.
- Xray 26.10.21, SHA256 архива
  `0eec3ed4163c273d8c8bf821f7d219e257921cf584aa3fb970715e458e631978`,
  сверено с файлом dgst официального релиза. Два VLESS/TLS 1.3 перехода,
  свой учебный CA, проверка имён сертификатов включена, доступ только
  10.1.50.10:8080. Новый Xray требует явного freedom.finalRules allow
  к частным адресам — добавлен узкий allow и завершающий block.
- Проверка конфига Xray выполняется от xray: запуск проверки от root создаёт
  root-owned журналы и мешает рабочей службе. Исправлено в итоговом install-скрипте.
- Проверки отказа: без IPsec ping не проходит, OSPF-маршрут исчезает,
  открытого GRE нет; после старта связь восстанавливается. Без relay Xray запрос
  не проходит, после старта успешно. Все временные отказы отменены.
- При проверке reboot выявлен systemd ordering cycle: GRE After=network-online

  IPsec и оба HTTP-пути восстановились. Протокол — outputs/after-reboot.txt.
